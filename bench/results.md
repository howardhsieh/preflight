# Benchmark: the 1,000 most-starred GitHub repositories

Re-run on 2026-10-22 with preflight v0.2.0 against the 1,000 most-starred public
repositories on GitHub (34k–555k stars), cloned with `preflight clone` (shallow, hooks
and submodules disabled). Popular repositories are treated as benign, so every `DANGER`
verdict is a false positive unless noted.

| Verdict | Repositories | Share |
|---|---|---|
| CLEAN | 924 | **92.8%** |
| REVIEW | 69 | 6.9% |
| DANGER | 3 | 0.3% |
| clone timed out (5 min) | 2 | — |

The v0.2.0 detection fixes (broadened chain resolution to Python/shell/TS payloads, and
not discounting a payload that a trigger explicitly runs — see the changelog) close
evasion gaps without moving these numbers: the verdict distribution is unchanged from
v0.1.0, with zero new false positives, because the stricter rules only fire when a
trigger executes a file that also carries a payload signal — rare in benign repos.

268 repositories produced no findings at all; 730 produced at least one informational
or low finding that does not affect the verdict.

## The three DANGER verdicts

All three are real instances of the mechanism preflight looks for, in repositories
that are not malicious:

| Repository | Rule | What it found |
|---|---|---|
| microsoft/vscode | PF101 | `extensions/copilot/.vscode/tasks.json` has a `watch` task with `runOn: folderOpen`. It really does run when the folder is opened. |
| QSCTech/zju-icicles | PF801 | Course material contains `LC301.exe.zip`, a Windows executable with a `.zip` extension. |
| minimaxir/big-list-of-naughty-strings | PF601 | The naughty-strings corpus includes invisible Unicode Tag characters, embedded in Go source. |

## What drives REVIEW

68 repositories were marked REVIEW: 39 because of at least one high-severity finding,
29 on accumulated medium findings alone (large monorepos with several install scripts,
plugin loaders and encoded test data).

| Rule | Repos | Typical case |
|---|---|---|
| PF602 bidi-control | 7 | Security tools whose source contains the characters they detect; a text-rendering benchmark corpus |
| PF502 agent-mcp-auto-approve | 6 | `enableAllProjectMcpServers: true` alongside a project `.mcp.json` |
| PF702 decode-and-execute | 5 | Launchers that build `exec(base64.b64decode(...))` command lines |
| PF803 symlink-escape | 4 | Symlinks to absolute paths on a maintainer's machine |
| PF201 devcontainer-host-command | 4 | `initializeCommand` running a repository script on the host |
| PF311 setup-py-suspicious | 4 | `setup.py` that both runs commands and fetches from the network |
| PF203 devcontainer-credential-mount | 3 | Dev containers mounting `~/.ssh` or `~/.aws` |
| PF103 vscode-repo-executable | 3 | Workspace settings pointing a tool at a script in the repository |

These are configurations that genuinely execute repository code on open, install, or
agent start. In a repository you trust they are conveniences; in one sent to you by a
stranger they are the attack surface, which is what the REVIEW verdict is meant to say.

## How the rules were tuned

The first run scored 73% CLEAN. Five rounds of tuning on this corpus brought it to 93%
without weakening the chain rule (a trigger that executes a suspicious file). The
false-positive patterns, roughly in order of impact:

1. **Git LFS pointers.** A clone without LFS smudging leaves a short text file where
   each image or font should be, which read as "script disguised as a font" — 52
   repositories. Pointers are now recognised and skipped.
2. **Minified bundles.** `atob` + `Function(` is how module loaders work. Files are
   classified as generated by line density, not only by path.
3. **Loose eval matching.** `RegExp.exec()`, `cdp.eval()`, `def eval(self)` and
   `eval()` in comments all matched. Dynamic evaluation now requires a variable
   argument, is not preceded by `.`, and comment lines are skipped.
4. **Legitimate agent configuration.** 3.8% of popular repositories ship Claude Code
   hooks, 3.9% ship MCP servers. These are medium findings now; the chain rule
   escalates them when the script they run is itself suspicious.
5. **Unicode.** 🏴󠁧󠁢󠁥󠁮󠁧󠁿 and the other subdivision flags are built from Tag characters;
   right-to-left translation files use bidi controls; zero-width spaces are everywhere
   in copied prose. Severity now depends on where the characters are and what they
   decode to.
6. **Scoring.** At most three findings per rule count towards the score, and REVIEW
   needs a high finding or a score of 50, so one noisy rule cannot condemn a repository.

## Reproducing

```bash
bench/run.sh 1000
python3 bench/summarize.py bench/results.jsonl
```

The raw per-repository results (`results.jsonl`, about 30 MB) are not committed.

## Sample re-run for the new vectors (2026-11-05, unreleased `vectors` branch)

The JetBrains, Zed, launch.json, pre-commit/lefthook, Nix, Gradle/Maven and
agent-hook rules (PF107, PF111–PF114, PF121–PF122, PF322, PF331–PF334, PF404–PF405,
PF506) were checked against a 30-repository sample weighted towards projects that
ship those files: JetBrains/kotlin, JetBrains/compose-multiplatform, JetBrains/ideavim,
ktorio/ktor, gradle/gradle, elastic/elasticsearch, spring-projects/spring-boot,
apache/kafka, apache/maven, google/guava, square/okhttp, facebook/react-native,
psf/black, pre-commit/pre-commit, pre-commit/pre-commit-hooks, home-assistant/core,
evilmartians/lefthook, zed-industries/zed, NixOS/nix, nix-community/home-manager,
direnv/direnv, openai/codex, anthropics/claude-code, oven-sh/bun, pytorch/pytorch,
django/django, pandas-dev/pandas, huggingface/transformers, ansible/ansible,
microsoft/vscode.

| Verdict | Repositories |
|---|---|
| CLEAN | 28 |
| REVIEW | 1 (oven-sh/bun, on pre-existing rules only) |
| DANGER | 1 (microsoft/vscode, the known `folderOpen` task) |

No new rule produced a high or critical finding on the sample. What they did produce:

| Rule | Findings | Why it is not a false positive |
|---|---|---|
| PF107 (info) | 21 in microsoft/vscode | `launch.json` programs, reported like `npm start` and only escalated by a chain |
| PF112 / PF113 (info) | kotlin, elasticsearch, ideavim | committed run configurations and plugin requests; a click is still needed |
| PF322 (low) | nix, home-manager, direnv, bun, codex | `shellHook`s that export variables |
| PF331 (medium) | kotlin, ktor | `cache-redirector.jetbrains.com`, a mirror of services.gradle.org |
| PF332 (low / medium) | 7 repos | `exec { commandLine 'git', ... }` (low); elasticsearch fetching `maven-metadata.xml` at build time (medium) |
| PF334 (low) | apache/maven | `-javaagent` in an integration-test fixture |
| PF404 (medium) | home-assistant/core | local hooks that run `script/run-in-env.sh`, a repository script |
| PF405 (low) | lefthook | lefthook's own `lefthook.yml` |

Two rounds of tuning came out of the first pass: PF332's network regex no longer
matches `readText()` on a file, `import java.net.*` or `HttpClient` inside a string
(kotlin, gradle, elasticsearch, okhttp), and PF333 ignores plugin repositories whose
path is interpolated from a property (`${systemTestMavenRepository}`), lives under
`build/`, or belongs to a documentation sample (gradle's `docs/.../maven-repo`
snippets), and is high only when the directory actually ships a jar.
